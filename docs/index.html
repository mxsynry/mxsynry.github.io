Project guide

Synchrose documentation

Synchrose is a Svelte dashboard that fetches public status and catalog data through source adapters, then keeps each observation attributable. It helps readers compare metadata; it does not host, verify or guarantee third-party binaries.

Accuracy boundary. “Updated”, “detected”, scores, prices and links are third-party claims. Always display the source and retrieval time, and never describe an item as safe solely because a source does.

System design

Architecture

The application separates source adapters, normalization, catalog state and presentation. The browser refreshes the four adapters concurrently, preserves successful results when another source fails, and keeps a last-known-good snapshot in local storage.

Runtime boundaries

  • The Worker exposes fixed routes for upstreams that require a server-side bridge; it is not an arbitrary proxy.
  • Each adapter validates and normalizes its own upstream response before it enters the shared catalog.
  • Source failures remain visible as health states while cached records continue to be usable.

Documented integration

WEAO API

Base domains documented by WEAO include weao.xyz, whatexpsare.online, weao.gg and whatexploitsaretra.sh. Use one primary and one fallback; do not fan out requests to every domain.

GEThttps://weao.xyz/api/versions/current
GEThttps://weao.xyz/api/versions/future
GEThttps://weao.xyz/api/versions/past
GEThttps://weao.xyz/api/status/exploits
GEThttps://weao.xyz/api/status/exploits/{exploit}
GEThttps://weao.xyz/api/sunc

Required request behavior

  • The browser adapter requests the primary WEAO domain, then tries its configured fallback if the request fails.
  • A failed request keeps the last successful browser snapshot and appears in the source health state.
  • Each observation stores its source, retrieval time and any update time supplied by that source.
  • Treat undocumented response properties as optional; never make rendering depend on them.

Directory integration

Voxlis and bypass.tools

These feeds use the Synchrose Worker because their upstream APIs do not allow direct browser requests.

GET/api/voxlis/catalog

The Voxlis route reads https://voxlis.net/api/directory/roblox. Each product platform remains a separate observation. Review notes arrive inline with the directory; the retired GitHub data files are no longer fetched.

  • Keep executor releases, Roblox target versions and historical benchmark builds separate.
  • Show a Myriad result's category, test date, counts and report link when supplied.
  • A cached upstream response stays marked as cached. Bridge retrieval time does not replace the source's update time.
  • Render editorial Markdown through the sanitizer and keep its attribution.
GET/api/bypass/catalog

The bypass.tools route reads https://bypass.tools/api/executors. It replaces Inject as the fourth catalog source. WEAO-synced rows keep that attribution. A bare UNC feature tag is not a measured score, and an sUNC value is not copied into UNC.

See the source research notes for definitions and the November 2026 migration.

External tool reference

RDD — Roblox Deployment Downloader

RDD is an MIT-licensed static browser application by Latte Softworks. Its public documentation says it assembles Roblox deployment resources in the browser from Roblox-hosted content. The July 2026 audit recorded separate WEAO and Pulsery deployments. Their interfaces may differ from the upstream project; these links are references rather than catalog data sources.

Deployment Observed public behavior Documentation status

Internal contract

Normalized data model

type CatalogItem = {
  id: string;
  name: string;
  aliases: string[];
  platforms: Platform[];
  sources: SourceId[];
  observations: SourceRecord[];
  working: 'working' | 'broken' | 'mixed' | 'unknown';
  detection: Detection | 'mixed';
  version: string | null;
  price: string | null;
  free: boolean | null;
  sunc: { min: number; max: number } | null;
  features: string[];
  conflicts: EvidenceConflict[];
};

type SourceRecord = {
  source: SourceId;
  fetchedAt: string;
};

The implementation types live in Others/Synchrose/src/lib/catalog/model.ts. Use null for unknown values and retain every source observation instead of flattening disagreement.

Deterministic behavior

Merge rules

  1. Normalize names for matching only; preserve the source display name.
  2. Apply an explicit, reviewed alias table. Do not use fuzzy matching for automatic merges.
  3. Retain all four source observations; no source silently owns a field across the entire catalog.
  4. When sources provide different factual values, show the conflict with both values—do not silently choose one.
  5. Every rendered status, score, price and review must retain provenance and retrieval time.

Maintenance

Operations runbook

Refresh

Use the dashboard refresh action or load the page with a configured Worker URL. Four adapters run concurrently and report health independently.

Failure

Keep the last-known-good browser snapshot, mark that source as cached, and show the upstream error without exposing sensitive headers.

Validation

Reject malformed URLs, impossible percentages and entries without names. Adapter schema failures should affect one source, not the whole page.

Testing

Run npm test, npm run check and npm run build from Others/Synchrose before deployment.

Release checklist

  • Keyboard navigation and mobile layout tested
  • Source fetch and stale-data paths tested
  • External URLs validated before rendering
  • No upstream HTML inserted unsanitized
  • Attributions, licenses and source timestamps visible
  • Production Pages deployment checked from a clean browser session

Guardrails

Safety, privacy and legal

  • Synchrose is an informational aggregator, not a malware scanner, endorsement or guarantee.
  • External downloads and purchase links are untrusted. Use clear domain labels and rel="noopener noreferrer".
  • Do not reproduce paid content, private APIs or third-party binaries.
  • Review music, images and video committed to the repository for redistribution rights; large bundled media also inflates clones and Pages deployment.
  • Document source terms and remove integrations promptly when a provider withdraws permission.

Project workflow

Contributing

  1. Open an issue describing the source or UI change and its documented permission.
  2. Add or update one source adapter; keep rendering independent of upstream response shape.
  3. Add fixtures for success, partial data, disagreement, 429 and offline behavior.
  4. Update this documentation and source-audit.json in the same pull request.
  5. Include the checks you ran and any behavior that still needs a live deployment to verify.
