Project guide

Synchrose documentation

Synchrose is a static, client-side dashboard that combines documented WEAO status data with public Voxlis repository data. It helps readers compare metadata; it does not host, verify or guarantee third-party binaries.

Accuracy boundary. “Updated”, “detected”, scores, prices and links are third-party claims. Always display the source and retrieval time, and never describe an item as safe solely because a source does.

System design

Architecture

The current application is a large single HTML file. The target design separates data refresh, normalization, presentation and documentation so a source change does not require editing the whole interface.

→

→
Static dashboardCloudflare Pages · cached JSON

Why snapshots are preferable

  • WEAO requires a specific User-Agent; browser JavaScript cannot reliably set that forbidden request header.
  • A scheduled job can respect rate limits, keep a last-known-good snapshot and record when each source was fetched.
  • The page remains usable when an upstream source is offline or blocks CORS.

Documented integration

WEAO API

Base domains documented by WEAO include weao.xyz, whatexpsare.online, weao.gg and whatexploitsaretra.sh. Use one primary and one fallback; do not fan out requests to every domain.

GEThttps://weao.xyz/api/versions/current
GEThttps://weao.xyz/api/versions/future
GEThttps://weao.xyz/api/versions/past
GEThttps://weao.xyz/api/status/exploits
GEThttps://weao.xyz/api/status/exploits/{exploit}
GEThttps://weao.xyz/api/sunc

Required request behavior

  • Send User-Agent: WEAO-3PService from the scheduled fetch job.
  • On 429, honor the returned reset information and keep the last-known-good snapshot.
  • Store fetchedAt, source domain and a content hash beside the response.
  • Treat undocumented response properties as optional; never make rendering depend on them.

Public repository data

Voxlis dataset

Voxlis is a static frontend backed by JSON and Markdown in localscripts/voxlis.NET. Synchrose should read the documented data files, not scrape rendered cards.

public/data/roblox/
├── prices.json
└── {Product}/
    ├── info.json      # platforms, links, tags, badges, visibility
    ├── points.json    # pro, neutral and con summaries
    ├── review.md      # long-form editorial review
    └── modals.json    # optional warnings and notes

Integration rules

  • Use a pinned commit SHA for reproducible builds, or update the pin through an auditable scheduled pull request.
  • Skip entries with hidden: true; tolerate optional or missing files.
  • Render Markdown as text through a vetted sanitizer. Never inject upstream HTML directly.
  • Keep editorial text attributed to Voxlis and separate it from factual status fields.

External tool reference

RDD — Roblox Deployment Downloader

RDD is an MIT-licensed static browser application by Latte Softworks. Its public documentation says it assembles Roblox deployment resources in the browser from Roblox-hosted content. WEAO, Pulsery and Inject each expose an RDD route or deployment interface; these are separate deployments and may not have identical code or behavior.

Internal contract

Normalized data model

type CatalogItem = {
  id: string;
  name: string;
  platforms: string[];
  productType?: string;
  version?: string;
  robloxVersion?: string;
  updated?: boolean | null;
  detected?: boolean | null;
  pricing: { label: string; free?: boolean; source: SourceRef };
  scores: { sunc?: number; unc?: number; source: SourceRef };
  links: { website?: string; discord?: string; purchase?: string };
  tags: string[];
  editorial?: { summary?: string; review?: string; source: SourceRef };
  provenance: SourceRef[];
};

type SourceRef = {
  name: 'weao' | 'voxlis';
  fetchedAt: string;
  sourceUrl: string;
  revision?: string;
};

Use null for “unknown”; do not convert unknown status to false. This avoids presenting missing data as a negative claim.

Deterministic behavior

Merge rules

  1. Normalize names for matching only; preserve the source display name.
  2. Apply an explicit, reviewed alias table. Do not use fuzzy matching for automatic merges.
  3. WEAO owns live update/detection fields; Voxlis owns its editorial review, tags and price catalog.
  4. When both sources provide a factual field and disagree, show “sources disagree” with both values—do not silently choose one.
  5. Every rendered status, score, price and review must retain provenance and retrieval time.

Maintenance

Operations runbook

Refresh

Run the snapshot workflow on a conservative schedule and by manual dispatch. Commit only when normalized content changes.

Failure

Keep the last-known-good JSON, mark it stale in the UI and record the upstream error without exposing sensitive headers.

Validation

Reject malformed URLs, impossible percentages and entries without names. Quarantine schema-breaking rows instead of breaking the page.

Performance

Split the 500+ KB monolith into modules, lazy-load media and move audio outside the documentation route.

Release checklist

  • Keyboard navigation and mobile layout tested
  • Source fetch and stale-data paths tested
  • External URLs restricted to https:
  • No upstream HTML inserted unsanitized
  • Attributions, licenses and source timestamps visible
  • Production Pages deployment checked from a clean browser session

Guardrails

Safety, privacy and legal

  • Synchrose is an informational aggregator, not a malware scanner, endorsement or guarantee.
  • External downloads and purchase links are untrusted. Use clear domain labels and rel="noopener noreferrer".
  • Do not reproduce paid content, private APIs or third-party binaries.
  • Review music, images and video committed to the repository for redistribution rights; large bundled media also inflates clones and Pages deployment.
  • Document source terms and remove integrations promptly when a provider withdraws permission.

Project workflow

Contributing

  1. Open an issue describing the source or UI change and its documented permission.
  2. Add or update one source adapter; keep rendering independent of upstream response shape.
  3. Add fixtures for success, partial data, disagreement, 429 and offline behavior.
  4. Update this documentation and source-audit.json in the same pull request.
  5. Use a draft pull request and include the Cloudflare preview or screenshots.
